# O Orb é uma forma simples de usar o telemóvel, para a vida pessoal e para o trabalho

- Data: 2026-11-03
- Estado: decidido

## Contexto
Os gestos foram desenhados antes de se saber para que serve o produto. Três decisões (D3, D6 e D8) dependiam disso.

## Opções
1. Assistente pessoal.
2. Ferramenta de trabalho.
3. Padrão de app para clientes da Hackie.
4. Deixar em aberto.

## Decisão
As opções 1 e 2 juntas. Nas palavras do Diogo: uma forma simples e fácil de usar o telemóvel, com foco na UX. São formas simples de representar dados e de interagir com eles.

**Os objetivos são organizar dados e visualizar dados, com uma boa UX.**

**O que se entrega:** um protótipo com esta interação e uma UI que o Diogo vai criando por cima. Não é uma app de produção.

## Porquê
O valor está na experiência (gestos, motion, representação dos dados) e não num domínio específico. Por agora, o conteúdo concreto pesa pouco.

## Consequências
- O protótipo deixa de ser só uma referência e passa a ser o produto a evoluir. A regra "`reference/` é só de leitura" deixa de fazer sentido.
- A interação (gestos, física) e a UI (aspeto) devem ficar separadas, para o Diogo trocar a UI sem tocar nos gestos.
- As fases 5 (construir a app) e 6 (testes formais) do `skills-plan.md` ficam fora de âmbito, salvo decisão em contrário.
- As views passam a ser **padrões de representação de dados** e não temas (ver `2026-11-03-views.md`).
- Os stories e o notebook servem tanto para a vida pessoal como para o trabalho. O conteúdo concreto define-se na fase 4.
- Critério para decisões futuras: na dúvida, escolher a opção mais simples de usar.
